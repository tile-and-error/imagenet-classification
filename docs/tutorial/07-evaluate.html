7. Evaluating a model

The Evaluator scores a graph on a whole dataset with a list of MetricBindings. It changes no weights.

from torchmetrics.classification import MulticlassAccuracy    # torchmetrics
from lwfm.evaluation.evaluator import Evaluator                # lwfm
from lwfm.evaluation.metrics import MetricBinding              # lwfm

metrics = [
    MetricBinding(f"top{k}",
                  MulticlassAccuracy(num_classes=10, top_k=k, average="micro"),  # torchmetrics
                  ["student.logits", "targets.class"])
    for k in (1, 5)
]
result = Evaluator().evaluate(
    pipeline, val_loader, metrics,                # val_loader: a torch DataLoader, or any list of batches
    device=torch.device("cpu"),                # torch: batches and metrics are moved here
    split_name="val",                               # lwfm: only names the events, e.g. eval/val/top1
    output_sink=ConsoleSink(),  # lwfm: optional; see slide 9
)

From PyTorch

  • MulticlassAccuracy(top_k=k) — counts a sample as right if the true class is among the k highest scores.
  • torch.inference_mode() — no gradients are tracked, so evaluation is faster and can't change any weights.
  • pipeline.eval() — dropout off, batch-norm uses its saved statistics.

From lwfm (ours)

  • Evaluator().evaluate(graph, data_loader, metric_bindings, *, curve_bindings, device, split_name, output_sink, training_step) — returns an EvaluationResult whose .metric_values is {name: float} and .curves is {name: table} (below).
  • to_device(batch, device) — moves every tensor in the batch; ids and other values stay as they are.
  • Errors — an empty loader, no metrics, two metrics with one name, or a metric that gives more than one number (e.g. average="none") each raise with the reason.
Why? Metrics are computed once at the end, not averaged per batch, so the last, smaller batch counts as much per sample as the others. The graph's mode is put back afterwards, so the trainer can call the same Evaluator for validation mid-training. Which average to use belongs to the metric object, so the Evaluator never guesses.

Curves: values that need the whole split

A metric keeps running totals, so it never holds more than one batch. A ROC curve or a confusion matrix needs every score at once, so it goes in a CurveBinding: a function that builds the table, plus the names it reads. The values are passed to the function in the order they are named, as with a metric's update.

from lwfm.evaluation.metrics import CurveBinding              # lwfm
from lwfm.results.curves import ConfusionMatrix               # lwfm

reads = ["student.logits", "targets.class"]
curves = [CurveBinding("confusion", ConfusionMatrix.from_scores, reads)]   # from_scores(logits, classes)
result = Evaluator().evaluate(
    pipeline, val_loader, metrics,
    curve_bindings=curves,                      # lwfm: optional
    device=torch.device("cpu"),
    output_sink=ConsoleSink(),                  # lwfm: also prints the table eval/val/confusion
)
result.curves["confusion"]   # ConfusionMatrix: matrix[true][predicted], 10 x 10

From torchmetrics

  • BinaryROC, BinaryPrecisionRecallCurve, MulticlassConfusionMatrix — compute the curve points and counts.
  • BinaryAUROC, BinaryAveragePrecision — compute the AUC and average precision stored with each curve.

From lwfm (ours)

  • ROCCurve.from_scores(scores, labels), PRCurve.from_scores(scores, labels) — a binary score [B] (logits or probabilities) and 0/1 labels.
  • ConfusionMatrix.from_scores(scores, labels, class_names=None) — a binary score [B] (positive above probability 0.5) or class scores [B, K] (the highest is predicted). For named classes, pass lambda s, y: ConfusionMatrix.from_scores(s, y, names).
  • CurveBinding(name, build, inputs) — any function works that takes one argument per name read and returns a Curve: a dataclass with a draw(axes) method. A mismatch, e.g. one name for a two-argument function, fails when the binding is created; a result with no draw fails when it is built.
  • Trainer.fit(curves=...) — builds them at the last validation, or also every curves_every_n_validations-th (slide 14); PlotSink draws each one (slide 9).
Why a function, not a torchmetrics metric? torchmetrics' curve metrics return bare tensors. The function turns them into a typed table, such as ROCCurve, that a sink can store as plain fields and PlotSink knows how to draw. Any other function of the split's outputs plugs in the same way.
