16. Distillation: a teacher is just another node

A teacher is a second ModelNode with frozen=True, and the distillation loss is one more LossBinding. The fit call is the same as on slide 13: the trainer has no special case for teachers.

flowchart LR
    IMG["inputs.image"] --> S["ModelNode 'student'<br/>small model, trained"]
    IMG --> T["ModelNode 'teacher'<br/>frozen=True"]
    S -- "student.logits" --> CE["LossBinding 'ce'"]
    Y["targets.class"] --> CE
    S -- "student.logits" --> KD["LossBinding 'kd'"]
    T -- "teacher.logits" --> KD
    CE --> SUM["LossComposer: 0.5·CE + w·KD"]
    KD --> SUM
    SUM --> BW["backward: only the student learns"]
class KDLoss(nn.Module):                                  # torch: a plain module, one number out
    def __init__(self, temperature=4.0):
        super().__init__()
        self.t = temperature

    def forward(self, student_logits, teacher_logits):    # argument order = binding's names
        s = F.log_softmax(student_logits / self.t, dim=-1)
        t = F.log_softmax(teacher_logits / self.t, dim=-1)
        return F.kl_div(s, t, log_target=True, reduction="batchmean") * self.t**2

# small_student: a cheaper ModelNode named "student" (it sees the image at half resolution)
teacher = ModelNode("teacher",
                    copy.deepcopy(graph.deployable_model("student")),  # lwfm: trained on slide 15
                    inputs="inputs.image", outputs="logits",
                    frozen=True)                           # lwfm: no gradients, always in eval mode
kd_graph = ExecutionGraph([small_student, teacher])        # lwfm: same class, two nodes
kd_loss = LossComposer([
    LossBinding("ce", nn.CrossEntropyLoss(), CE_READS, weight=0.5),
    LossBinding("kd", KDLoss(), ["student.logits", "teacher.logits"], weight=0.5),
])
result = Trainer(device="cpu", max_epochs=3, log_every_n_steps=20).fit(
    kd_graph, train_loader, kd_loss,
    torch.optim.SGD(small_student.parameters(), lr=0.1),  # torch: only the student is optimised
    val_loader=val_loader, metrics=metrics,
    # lwfm: the KD weight rises from 0 to 0.5 over the first 20 steps
    callbacks=[LossWeightSchedule("kd", lambda step: 0.5 * min(1.0, step / 20))],
    output_sink=ConsoleSink(),
)

From PyTorch

  • F.log_softmax, F.kl_div — the KL divergence between the softened teacher and student distributions.
  • copy.deepcopy — a separate copy of the trained weights, used as the teacher.

From lwfm (ours)

  • ModelNode(..., frozen=True) — sets requires_grad=False, runs under no_grad, and stays in eval mode even when the trainer calls graph.train().
  • LossWeightSchedule(binding_name, weight_at_step) — sets a binding's weight to weight_at_step(global_step) before every batch.
  • Optimizer check — leave a trainable node (e.g. a projector) out of the optimizer, and fit refuses to start, naming it (slide 18).
Why? Distillation is wiring, not a new training loop: one node and one loss entry. Several teachers mean more nodes with distinct names. The deployable model is still just kd_graph.deployable_model("student") (slide 8), with no teacher inside it.
