18. Settings, sweeps, and mistakes caught early

Loop settings such as mixed precision are constructor arguments. Because the trainer keeps nothing between runs, one trainer can run a whole sweep. And fit checks its inputs before the first batch.

trainer = Trainer(
    device="cpu",
    max_epochs=3,
    precision="bf16",             # lwfm: forward pass in bfloat16; weights stay fp32
    accumulate_grad_batches=2,    # lwfm: one optimizer step per 2 batches (effective batch 64)
    gradient_clip_norm=1.0,       # lwfm: clip the gradient norm before each step
)
best_top1 = {}
for lr in (0.01, 0.1, 0.5):
    seed_everything(0)                                     # lwfm: same initial weights each run
    student = make_student()                               # fresh objects for every run
    result = trainer.fit(
        ExecutionGraph([student]), train_loader, loss,
        torch.optim.SGD(student.parameters(), lr=lr),       # torch: a new optimizer per run
        val_loader=val_loader, metrics=metrics,
    )
    best_top1[lr] = round(result.best("top1")["top1"], 3)
best_top1
{0.01: 0.919, 0.1: 0.906, 0.5: 0.881}
SettingDoes
max_epochs, max_stepswhen to stop; max_steps=3 makes a quick smoke test
precision"fp32" (default), "bf16" or "fp16" (with gradient scaling)
accumulate_grad_batchesadd up gradients over k batches before each optimizer step
gradient_clip_normclip the total gradient norm
val_every_n_steps, log_every_n_stepshow often to validate and log
step_fnreplace what one step computes; the rest of the loop stays

With an output_sink, fit records these settings, plus the optimizer's hyperparameters, the scheduler, the callbacks and the torch seed, as one trainer/settings event at step 0, so every run says how it was trained.

Mistakes fail before training starts

projector = ModelNode("projector", nn.Linear(K, K), inputs="student.logits", outputs="z")
graph = ExecutionGraph([student, projector])               # projected_loss reads "projector.z"
Trainer(device="cpu", max_epochs=1).fit(
    graph, train_loader, projected_loss,
    torch.optim.SGD(student.parameters(), lr=0.1),         # the projector was left out
)
ValueError: trainable parameters missing from the optimizer:
['nodes.projector.module.weight', 'nodes.projector.module.bias']
Checked before the first batchInstead of
every name a loss or metric reads existsa crash at the first step
every trainable parameter is in the optimizera node that silently never learns
a scheduler comes with its interval, and belongs to this optimizera learning rate that's wrong for the whole run
callbacks only define real hooks (on_validation_ended is refused)a callback that silently never runs
Why? A training run can take hours. Every check here costs milliseconds, and turns a silent mistake into an error message that names the problem.
