4. ModelNode: wrapping a model

A ModelNode wraps any nn.Module, unchanged. It says what the model reads and what it writes.

from torch import nn                                    # torch
from torchvision.models import resnet18                 # torchvision: a standard model
from torchvision.transforms import v2                   # torchvision: transforms, as nn.Modules

from lwfm.core.graph import ModelNode                   # lwfm

MEAN, STD = (0.485, 0.456, 0.406), (0.229, 0.224, 0.225)  # ImageNet statistics

student = ModelNode(
    "student",                                          # lwfm: the node's name
    nn.Sequential(                                      # torch: run these one after another
        v2.Resize((64, 64), antialias=True),            # torchvision: resize (skipped if 64x64)
        v2.Normalize(MEAN, STD),                        # torchvision: (x - mean) / std
        resnet18(num_classes=10),                       # torchvision: untouched
    ),
    inputs="inputs.image",   # lwfm: passed to forward() as its 1st argument
    outputs="logits",        # lwfm: what forward() returns, stored as "student.logits"
)
student(batch["inputs"]["image"])
{'student.logits': tensor of shape [8, 10]}

From PyTorch

  • nn.Module — the base class of every PyTorch model. You write forward(); PyTorch tracks the weights.
  • nn.Sequential(a, b) — an nn.Module that runs b(a(x)). One input in, one output out.
  • resnet18 — a ready-made torchvision model. We never edit or subclass it.
  • v2.Resize v2.Normalize — torchvision transforms. They are nn.Modules, so any preprocessing you like is a step in the nn.Sequential.

From lwfm (ours)

  • ModelNode(name, module, inputs, outputs) — is itself an nn.Module. inputs go in by position; outputs are prefixed with the node name.

What a model may return

forward() returnsoutputsNode outputs
a tensor"logits"student.logits
a tuple (a, b)["logits", "features"]both, in order
a dict["logits", "features"]only the listed keys
Why? Wrapping instead of subclassing means any model works as it is: torchvision, timm or your own. Passing values by position means you never need to know what a model calls its arguments. And because preprocessing is the first step of the model's nn.Sequential, the saved model always carries its own preprocessing.
