8. Training vs inference

Training uses the whole framework. Inference uses only the trained model, pulled out as a plain nn.Module.

model = graph.deployable_model("student")        # lwfm: returns the node's module itself
model.eval()                                     # torch: switch layers to inference behaviour
torch.save(model.state_dict(), "weights.pt")     # torch: save only the weights

with torch.inference_mode():                     # torch: no gradient bookkeeping
    probs = model(torch.rand(1, 3, 120, 80)).softmax(dim=-1)  # any image size; resized inside
model is the same nn.Sequential(InputAdapter, resnet18) we built on slide 4; probs has shape [1, 10]

From PyTorch

  • .train() / .eval() — switch layers like dropout and batch-norm between training and inference behaviour.
  • state_dict() / torch.save — the model's weights as a dict, saved to a file.
  • torch.inference_mode() — runs faster and uses less memory by not tracking gradients.

From lwfm (ours)

  • deployable_model(node) — returns that node's module, sharing weights with the graph (no copy). You must name the node: the graph doesn't know which one is "the student".
Why? The thing we measure and ship must be the student alone: no teachers, no losses, no framework. Because it's a plain nn.Module with its preprocessing inside, it can be benchmarked fairly, reloaded, or wrapped for TIAToolbox.
