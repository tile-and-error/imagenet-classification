3. Batches and names

A batch is a plain dict with three groups. Every value in it, and every model output, has a name.

import torch

batch = {                                              # a plain Python dict
    "inputs": {"image": torch.rand(8, 3, 96, 96)},     # torch: float tensor [B, C, H, W] in [0, 1]
    "targets": {"class": torch.randint(0, 10, (8,))},  # torch: int64 labels [B]
    "meta": {"sample_id": [f"s{i}" for i in range(8)]},  # anything that isn't a tensor
}

from lwfm.core.names import resolve                    # lwfm: look a value up by name

resolve("inputs.image", batch, {})    # -> batch["inputs"]["image"]
resolve("targets.class", batch, {})   # -> batch["targets"]["class"]

The two kinds of name

NameMeansExample
<group>.<key>A value in the batch (group = inputs, targets or meta)inputs.image
<node>.<output>An output of a model nodestudent.logits

From PyTorch

  • torch.Tensor — the numbers. Shapes are written [B, C, H, W]: batch, channels, height, width.
  • DataLoader — can batch dicts like this one with no extra code.

From lwfm (ours)

  • resolve(name, batch, outputs) — finds a value by name; a typo raises UnknownNameError that says which name was wrong.
  • Name — just a string, like "student.logits".
Why? A dict needs no special support: PyTorch's DataLoader, saving and device tools already handle it. String names make the wiring readable in one place, and they can be written in a config file or a log.
