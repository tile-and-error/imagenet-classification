9. Recording results

Training code emits events. Sinks decide where they go. The training code never knows about files.

from lwfm.results.events import RunEvent                        # lwfm
from lwfm.results.router import OutputRouter                    # lwfm
from lwfm.results.sinks import ConsoleSink, LocalFileSink       # lwfm

with OutputRouter(LocalFileSink("runs/demo"), ConsoleSink()) as router:   # lwfm
    for step in range(3):
        total, terms = loss_fn(batch, pipeline(batch))
        optimizer.zero_grad()
        total.backward()
        optimizer.step()
        router.write(RunEvent("scalar", "train/loss/total", total.detach(),  # torch tensor is fine;
                             stage="fit", step=step))                       # stored as a number

Saving weights: a file, plus an event that points to it

torch.save(model.state_dict(), "runs/demo/student.pt")         # torch: the weights, in their own file
router.write(RunEvent("artifact", "fit/checkpoint", "student.pt"))  # lwfm: the log records where it is

Sinks never receive tensors: a one-number tensor becomes a plain number, anything bigger is refused. Large data goes to its own file; the event only says where it is.

FileWrittenHolds
manifest.jsonat the startversions, machine, your settings
status.jsonstart, then at the endrunning → completed / failed (with traceback) / interrupted
events.jsonlevery event, at onceone line per event, so a crashed run keeps its data
summary.jsonat the endthe last value of every scalar

LocalFileSink(run_dir, file_format="yaml") or "csv" writes every one of these files in that format instead (events.yaml, events.csv, ...). PlotSink(plot_dir), in lwfm.results.plots, saves a PNG of each scalar against its step, and of each curve logged as a table of columns (e.g. a ROC curve), when it closes.

From PyTorch

  • total.detach() — a tensor with no gradient attached. A one-number tensor is stored as a plain number; bigger tensors are refused (save a file instead).

From lwfm (ours)

  • RunEvent(kind, name, value, stage, step) — kind is scalar, table, artifact, status or message.
  • OutputRouter(*output_sinks) — sends each event to every sink. Used with with, it records the final status even if the run crashes.
  • OutputSink — the interface. Code that produces results only depends on OutputSink; the router is one too.
Why? Sinks sit outside the computation, and nothing reads back from them. Remove every sink and training computes exactly the same thing. Adding a new destination (plots, MLflow) is a new sink, with no change to training code.
