13. The Trainer: training in one call

The Trainer runs the training loop for any graph, loss and PyTorch optimizer. It is the hand-written loop from slide 9 plus the bookkeeping around it: moving data to the device, counting steps, validating, logging and stopping.

Part 2 of the tutorial continues from the setup in examples/trainer.ipynb: make_student() builds a one-node student (slide 4), CE_READS is ["student.logits", "targets.class"], and train_loader / val_loader are lists of batch dicts (slide 3).

from lwfm.training import Trainer, seed_everything          # lwfm

seed_everything(0)                                           # lwfm: seed before building, so weights repeat
student = make_student()                                     # lwfm: a ModelNode (slide 4)
graph = ExecutionGraph([student])                            # lwfm: a one-node graph (slide 5)
loss = LossComposer([LossBinding("ce", nn.CrossEntropyLoss(), CE_READS)])  # lwfm + torch (slide 6)
optimizer = torch.optim.SGD(student.parameters(), lr=0.1)    # torch: any optimizer, built by you

trainer = Trainer(device="cpu", max_epochs=3)                # lwfm: HOW to train (the loop settings)
result = trainer.fit(graph, train_loader, loss, optimizer)   # lwfm: WHAT to train (this run's objects)
result
TrainingResult(global_step=60, epochs_completed=3, stop_reason='max_epochs', history=[])
# 3 epochs × 20 batches = 60 optimizer steps; no validation ran, so history is empty

What fit runs, without the bookkeeping

graph.train()                                     # torch: training mode (frozen teachers stay in eval)
for epoch in range(3):
    for batch in train_loader:
        total, terms = loss(batch, graph(batch))  # lwfm: forward pass, then the weighted loss
        optimizer.zero_grad()                     # torch
        total.backward()                          # torch
        optimizer.step()                          # torch

From the same seed, this loop and trainer.fit give bit-identical weights (a unit test checks it). The trainer adds bookkeeping, never different maths.

From PyTorch

  • torch.optim.SGD — or AdamW, or any optimizer: you build it, so the trainer never needs to know which.
  • train_loader — a DataLoader, or any iterable of batch dicts.

From lwfm (ours)

  • Trainer(device, max_epochs, max_steps, ...) — the loop settings. At least one of max_epochs / max_steps is required.
  • trainer.fit(graph, train_loader, loss, optimizer, ...) — runs training and returns a TrainingResult: global_step, epochs_completed, stop_reason, history.
  • seed_everything(seed) — seeds Python, NumPy and torch.
Why split the constructor from fit? The constructor holds how to train, and keeps nothing between runs, so one trainer can run a whole sweep (slide 18). Everything with state (weights, optimizer momentum) is passed to fit fresh for each run. And every input is a plain PyTorch object, so you can always drop back to your own loop.
