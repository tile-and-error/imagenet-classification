15. Callbacks: changing training without changing the loop

A Callback is an object whose on_* methods the trainer calls at fixed points. Each one receives the TrainingState: the graph, the optimizer, the step counters and the latest metrics.

from lwfm.training import Callback                         # lwfm
from lwfm.training.callbacks import EarlyStopping          # lwfm: a ready-made callback

class PrintValidation(Callback):
    def on_validation_end(self, state, metrics):           # override only the hooks you need
        top1 = metrics["top1"]
        print(f"epoch {state.epoch}, step {state.global_step}: top1 = {top1:.3f}")

result = Trainer(device="cpu", max_epochs=50).fit(
    graph, train_loader, loss, optimizer,
    val_loader=val_loader, metrics=metrics,
    # lwfm: stop once top1 has failed to improve for 2 validations in a row
    callbacks=[
        PrintValidation(),
        EarlyStopping("top1", max_validations_without_improvement=2),
    ],
)
result.stop_reason, result.epochs_completed
epoch 1, step 20: top1 = 0.900
epoch 2, step 40: top1 = 0.887
epoch 3, step 60: top1 = 0.887
('stopped', 3)                            # stopped long before 50 epochs

When each hook runs

Each box is a loop, or a step that only sometimes happens. The hooks inside it run top to bottom, and a nested box runs at that point in its parent's list.

Fit one call to trainer.fit(...)
  • on_fit_start
  • Epoch repeats until max_epochs, max_steps or state.should_stop
    • on_epoch_start
    • Batch repeats for each batch of train_loader
      • on_step_start(batch)
      • on_after_backward
      • Optimizer step only at an accumulation boundary
        • on_after_optimizer_step
      • on_step_end(output)
      • Validation at a boundary, every val_every_n_steps (if set)
        • on_validation_end(metrics)
    • on_epoch_end skipped if training stopped mid-epoch
    • Validation after the epoch, if val_every_n_steps is unset
      • on_validation_end(metrics)
  • Final validation unless the last step was just validated
    • on_validation_end(metrics)
  • on_fit_end(result) also on Ctrl-C or a crash, before re-raising
  • An accumulation boundary is every accumulate_grad_batches-th batch, and the last batch of each epoch. With the default of 1, every batch is one.
  • on_after_backward and on_after_optimizer_step come from the helpers in lwfm.training.steps, so they fire only if step_fn uses them (default_step does).
  • Validation runs only when val_loader and metrics are given. Within one hook, callbacks run in the order they were passed to fit.
HookRunsTypical use
on_fit_start / on_fit_endonce, before the first batch / at the end (also after Ctrl-C)check settings; save the final state
on_epoch_start / on_epoch_endaround each full pass over the dataper-epoch schedules and summaries
on_step_start / on_step_endaround each batchper-step schedules, e.g. a loss weight
on_after_backwardgradients exist, before the optimizer stepinspecting gradients
on_after_optimizer_stepthe weights have just changedan EMA teacher (self-distillation)

Ready-made callbacks, in lwfm.training.callbacks

From PyTorch

  • Nothing new. state.optimizer and state.graph are the same torch.optim optimizer and nn.Module you passed to fit.

From lwfm (ours)

  • Callback — every hook does nothing by default.
  • TrainingState — graph, loss, optimizer, global_step, epoch, last_val_metrics, ...
  • state.should_stop = True — ends the run cleanly; stop_reason becomes "stopped".
Why? Each technique that acts at a point in time (a schedule, early stopping, an EMA teacher) is a small object, not an edit to the loop, so techniques combine by listing them. Because hooks default to doing nothing, a misspelled one such as on_validation_ended would never run, so fit refuses it before training starts. To change what one step computes (e.g. two forward passes per step), replace the step itself with Trainer(step_fn=...) instead.
