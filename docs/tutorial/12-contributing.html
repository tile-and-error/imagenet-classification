12. Getting started

Set up and check everything works

uv sync --extra examples --inexact      # install, plus the notebook kernel
uv run pytest -q                        # all tests (CPU only, a few seconds)
uv run ruff format . && uv run ruff check .
uv run --with pyright pyright lwfm      # type check

Where things are

PLAN.mdThe source of truth: what to build, in which order, and why.
lwfm/core/Names, ModelNode, ExecutionGraph, losses, to_device.
lwfm/models/, lwfm/evaluation/, lwfm/results/model builders (coming); MetricBinding, Evaluator; events, router, sinks.
examples/building_blocks.ipynbEverything on these slides, runnable.
tests/unit/One test file per module.

How to contribute a piece

  1. Find its place on slide 10. Don't add a new mechanism if an existing one fits.
  2. Write it as a plain PyTorch module or function, or a subclass of the matching lwfm interface.
  3. Add tests: one that it works, one that it fails clearly when misused.
  4. Add a runnable example to the notebook. If it isn't runnable yet, it stays in PLAN.md.
  5. Check the existing examples and tests still pass unchanged.

What's done, what's next (Phase 1)

doneGraph building blocks and the preflight shape check, losses, metric bindings and the evaluator (top-1/top-5), events and sinks.
nextData modules (fake data, ImageFolder, fixed splits), Trainer, benchmarks, checkpoints, stages and recipe, the python -m lwfm.run command.

Rule from the plan: no distillation or compression code until every Phase 1 test passes.
