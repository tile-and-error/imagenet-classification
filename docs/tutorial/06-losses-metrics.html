6. Losses and metrics

A binding pairs a normal loss or metric with the names of the values it reads.

import torch
from lwfm.core.losses import LossBinding, LossComposer   # lwfm

loss_fn = LossComposer([                                  # lwfm: adds up all its losses
    LossBinding("ce", nn.CrossEntropyLoss(),              # torch: the loss, unchanged
                ["student.logits", "targets.class"]),     # lwfm: CrossEntropyLoss(input, target)
])
optimizer = torch.optim.SGD(graph.parameters(), lr=0.1)   # torch

graph.train()                                     # torch: training mode
for step in range(20):
    total, terms = loss_fn(batch, graph(batch))   # lwfm: total, and each term for logging
    optimizer.zero_grad()                         # torch
    total.backward()                              # torch: compute gradients
    optimizer.step()                              # torch: update weights
terms == {'ce': tensor(0.0006)}    # one batch, learned by heart: loss falls towards 0
from torchmetrics.classification import MulticlassAccuracy   # torchmetrics
from lwfm.evaluation.metrics import MetricBinding            # lwfm

top1 = MetricBinding(
    "top1",                                                  # lwfm: the result's name
    MulticlassAccuracy(num_classes=10, average="micro"),     # torchmetrics: unchanged
    ["student.logits", "targets.class"],                     # lwfm: update(preds, target)
)
top1.update(batch, graph(batch))   # lwfm: looks the values up, calls metric.update(preds, target)
top1.metric.compute()              # torchmetrics: accuracy over every sample seen so far

From PyTorch

  • nn.CrossEntropyLoss — a standard loss: (input, target) → one number.
  • total.backward() — PyTorch's autograd works out every weight's gradient.
  • torch.optim.SGD — updates the weights from those gradients.
  • torchmetrics.Metric — a metric that keeps running totals: reset(), update(preds, target) per batch, compute() at the end. average="micro" counts every sample equally.

From lwfm (ours)

  • LossBinding(name, loss, reads, weight=1.0) — any loss: a torch loss, your own nn.Module, or a plain function.
  • LossComposer(bindings) — returns total = Σ weight × loss, plus each loss detached (no gradient) for logging. A NaN or non-scalar loss raises an error naming it.
  • MetricBinding(name, metric, reads) — update() looks values up by name and passes them in order. Resetting and computing is the Evaluator's job (next slide).
Why? Adding a distillation loss later is one more LossBinding that reads "teacher.logits". No loss reads a hidden shared object, so each one can be tested on its own, and a wrong name fails with that name in the message.
