17. Saving trained models

Sinks record results, but never hold tensors (slide 9). So saving is two steps: write the weights to a file, then send an artifact event that holds the file's path. ModelCheckpoint does both during training.

from lwfm.training.callbacks import ModelCheckpoint       # lwfm

run_dir = Path(tempfile.mkdtemp()) / "demo_run"
with OutputRouter(LocalFileSink(run_dir)) as sink:         # lwfm: fit inside, so a crash is recorded
    Trainer(device="cpu", max_epochs=3).fit(
        graph, train_loader, loss, optimizer,
        val_loader=val_loader, metrics=metrics,
        callbacks=[ModelCheckpoint(run_dir, node="student", monitored_metric="top1")],  # lwfm
        output_sink=sink,
    )

FileHoldsWritten
checkpoints/best.ptthe student's weights only (deployable_model("student").state_dict())whenever monitored_metric improves; only if one is given
checkpoints/last_weights.ptthe student's final weights only, in the same form as best.ptwhen training ends, including after Ctrl-C
checkpoints/last.ptthe full training state: graph, optimizer, scheduler, counters (for resuming)when training ends, including after Ctrl-C

Loading the model back

restored = make_student()                                  # lwfm: rebuild the same architecture ...
weights = torch.load(run_dir / "checkpoints/best.pt", weights_only=True)  # torch: ... then load weights
restored.module.load_state_dict(weights)                   # torch: from here on, a plain nn.Module
Evaluator().evaluate(ExecutionGraph([restored]), val_loader, metrics, device=torch.device("cpu"))
EvaluationResult(metric_values={'top1': 0.8999999761581421})   # the best validation score, as saved

From PyTorch

  • state_dict() / torch.save — the weights as a dict of tensors, in a file.
  • torch.load(..., weights_only=True) — loads tensors only, never code, so a checkpoint can't run anything.

From lwfm (ours)

  • ModelCheckpoint(run_dir, node, monitored_metric=None, goal="max") — the run directory, which node to save, and which metric decides "best". save_last=False skips the two end-of-run files.
  • Paths are relative to the run directory, so a run folder can be moved without breaking its records.
Why? A file plus an event keeps the record small and readable, and lets each sink decide what an artifact means: the console prints it, and a future MLflow sink could upload it. Only the student is saved as "best": that is the model we ship and benchmark. To compare runs at a fixed schedule, leave monitored_metric unset and use last_weights.pt, so every run stops at the same point.
